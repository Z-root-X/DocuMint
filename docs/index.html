DocuMint is a local-first document automation and high-throughput dispatch engine developed in Python by software engineer Zihad Hasan[1]. Designed to replace traditional mail merge tools, DocuMint combines structured tabular data from spreadsheet sources (Microsoft Excel and CSV) with formatted Word documents (.docx) to compile personalized certificates, admit cards, transcripts, and invoices at scale[2].

Unlike cloud-hosted software-as-a-service (SaaS) document generation APIs, DocuMint executes 100% of data manipulation, vector PDF rendering, and SMTP/Outlook email dispatch locally on the host machine. This architecture ensures zero cloud data transmission, meeting strict privacy standards for educational institutions, corporate human resource departments, and healthcare administrators managing confidential records[3].

1 Background and Problem Statement

Bulk document generation in enterprise and academic settings historically suffered from three critical systemic limitations:

  1. Formatting Degradation in Legacy Mail Merge: Standard Microsoft Word mail merge frequently alters typeface hierarchies, destroys nested table alignments, and requires cumbersome manual GUI navigation for every single batch operation[2].
  2. Cloud Data Leakage and Confidentiality Violations: Modern cloud-based document generation APIs (such as DocuSign, PandaDoc, and third-party Zapier plugins) require transmitting sensitive identity numbers, salary slips, and academic evaluations to remote multi-tenant servers, violating internal security policies.
  3. Dispatch Disconnect and Manual Attachment Overhead: Traditional workflows require generating files in one program, converting them manually to PDF in a second tool, and manually attaching each individual PDF to separate recipient emails in a third program.

2 Architecture and System Design

DocuMint is architected into four decoupled subsystems that operate in a synchronized pipeline:

2.1 Template Merge Pipeline

The core parsing engine scans the underlying XML run tree of Word documents without destroying character-level styles. Rather than replacing raw paragraph string content (which resets bold, italic, and color properties in the OpenXML schema), DocuMint performs granular run-level token substitutions.

The parser supports multiple placeholder syntaxes to maintain cross-system compatibility:

  • Angle Bracket Notation: <Recipient_Name>
  • Mustache / Jinja Notation: {{Recipient_Name}}
  • Square Bracket Notation: [Recipient_Name]

2.2 Universal PDF Engine

To achieve true cross-platform compatibility across Windows, Linux, and macOS, DocuMint employs a prioritized fallback cascade (UniversalDocumentConverter):

  1. Tier 1 (Windows Native): Invokes Microsoft Word COM automation via win32com.client for pixel-perfect fidelity.
  2. Tier 2 (Headless Fallback): Utilizes the pure-Python docx2pdf package.
  3. Tier 3 (POSIX Server Fallback): Executes headless libreoffice --headless --convert-to pdf on Linux/Docker servers.

2.3 Multi-Thread Dispatcher

The dispatch module orchestrates a worker thread pool allowing concurrent email transmission with automatic attachment binding. It provides native support for SSL/TLS SMTP relays (such as Gmail, SendGrid, Amazon SES) and local COM automation for desktop Microsoft Outlook clients.

2.4 Persistent SQLite Audit Ledger

Every execution session writes comprehensive telemetry to a local SQLite database (history.db), logging timestamped recipient identifiers, dispatch status codes, PDF hash signatures, and retry failure stack traces.

5 Implementation and Usage

DocuMint is distributed as an open-source Python library and local web studio.

5.1 Installation

# Clone repository
git clone https://github.com/zihaaaad/DocuMint.git
cd DocuMint

# Install dependencies via pip or uv
pip install -r requirements.txt

5.2 Launching the Local Dashboard

# Run local execution server
python src/main.py

# Access web interface at:
# http://localhost:5000
